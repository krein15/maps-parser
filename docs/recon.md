# Разведка источников: 2ГИС и Яндекс Карты

Шаг 0 проекта: прежде чем писать код, выяснить, откуда брать данные, что именно отдаётся
и где у источника потолок. Всё ниже проверено вживую 24 октября 2026 года обычным
HTTP-клиентом (`urllib`, без браузера и без ключей), запросы — из Тюмени.

## Главный вывод

Обе карты отдают готовые данные **в первом же HTML-ответе**: страницы собираются на сервере,
а состояние страницы лежит в теле документа отдельным куском JSON. Значит, парсеру не нужны
ни ключ API, ни Selenium с Chromium: хватает `requests` и разбора JSON. Это определило всё
остальное — размер `.exe` (десятки мегабайт, а не 300), скорость и то, что сбор не ломается
от перевёрстки сайта (ломается только при смене формата состояния).

## Почему не официальные API

| | Что мешает |
|---|---|
| **Яндекс, API Поиска по организациям** | Условия прямо запрещают сохранять результаты поиска, использовать их без карты и показывать на карте другого поставщика. Выгрузка организаций в Excel — ровно то, что запрещено. |
| **2ГИС, Places API** | Демо-ключ отдаёт максимум 5 страниц по 10 объектов, а контакты (`contact_groups`) требуют отдельного платного разрешения на ключ. Для бесплатной программы это нерабочий вариант. |

Поэтому источник — открытая часть сайтов: то, что видит любой человек, открывший карту в браузере.

## 2ГИС

### Поиск

```
https://2gis.ru/<город>/search/<запрос>[/page/<N>]
```

Состояние — в теле страницы, присваиванием `var initialState = JSON.parse('…');`.
Строка внутри одинарных кавычек — JSON с экранированием в стиле JS.

- `data.search.profile.<uuid>.data` → `total`, `pages`, `currentPage`;
- `data.entity.profile` → словарь «id объекта → карточка» — **12 объектов на страницу**.

Карточка из выдачи: `name`, `name_ex` (отдельно название и тип), `address_name`, `address`
(с улицей, домом и индексом), `point` (`lat`/`lon`), `rubrics`, `reviews`
(`general_rating`, `general_review_count_with_stars`), `schedule`, `org.id`, `is_promoted`.
**Контактов в выдаче нет.**

### Потолок: пять страниц

`pages` в состоянии обещает хоть 203 страницы, но сервер отдаёт только первые пять:
начиная с шестой возвращается первая (`currentPage: 1`). Проверено, что это именно потолок
страницы, а не ограничение частоты: сразу после отказа страница 3 снова отдаётся нормально.

**60 объектов на один запрос** — с этим и приходится работать.

### Обход потолка: плитки карты

Вьюпорт карты в адресе строго сужает поиск:

```
https://2gis.ru/<город>/search/<запрос>?m=<lon>,<lat>/<zoom>
```

Проверка на «магазин» в Тюмени: плитка на западе вернула объекты с долготой 65.4655–65.4809,
плитка на востоке — 65.5946–65.6562, пересечения нет. Значит, город режется на плитки,
по каждой берутся свои пять страниц, дубликаты убираются по id.

Границы города брать неоткуда не нужно: они лежат в состоянии любой страницы города —
`data.region.profile.<id>.data.bounds` в виде `POLYGON((…))`.

### Карточка организации

```
https://2gis.ru/<город>/firm/<id>
```

Здесь появляется `contact_groups` — ради него всё и затевалось:

```json
{"contacts": [
  {"type": "phone",   "text": "+7 (3452) 66‒67‒07", "value": "+73452666707"},
  {"type": "website", "text": "oneraf-coffe.ru",    "value": "http://link.2gis.ru/…?http://oneraf-coffe.ru"},
  {"type": "email",   "text": "one.raf@mail.ru",    "value": "one.raf@mail.ru"},
  {"type": "vkontakte", "url": "https://vk.com/club228815967"},
  {"type": "whatsapp",  "url": "https://wa.me/79923005297?text=…"},
  {"type": "telegram",  "url": "https://t.me/+79923005297"}
]}
```

Ловушки:
- у `website` в `value` лежит счётчик переходов `link.2gis.ru/…?<настоящий адрес>` — настоящий
  адрес либо в `text`, либо после `?` в конце ссылки;
- телефон в `text` разделён символом `‒` (U+2012), а не дефисом;
- `id` объекта и `org.id` — **разные числа**; карточка открывается только по id объекта.

Цена вопроса: один дополнительный запрос на каждую организацию.

## Яндекс Карты

### Поиск

```
https://yandex.ru/maps/<geoId>/<город>/search/<запрос>/?page=<N>
```

Состояние — в самом большом `<script type="application/json">` на странице (около 1,1 МБ).
Результаты: `stack[0].results` → `items` (**25 объектов на страницу**), `totalResultCount`.

И это главное отличие от 2ГИС: **контакты уже в выдаче**. У объекта есть `title`,
`fullAddress`, `coordinates`, `phones` (с нормализованным `value`), `businessLinks`
(сайт и соцсети), `ratingData` (`ratingValue`, `ratingCount`, `reviewCount`),
`categories`, `workingTimeText`, `currentWorkingStatus`, `chain`, `seoname`, `id`,
`businessProperties` (среди них `has_verified_owner` — подтвердил ли владелец карточку).

Один запрос — 25 организаций со всеми контактами. Это в разы дешевле 2ГИС.

### Пагинация

Работает параметром `?page=N`, проверено до сороковой страницы: тысяча уникальных
организаций, новые продолжают приходить. `totalResultCount` — оценка, она растёт по мере
листания (45 на первой странице, 1741 на сороковой), доверять ей как «сколько всего» нельзя;
признак конца — страница без новых id.

### Карточка организации

```
https://yandex.ru/maps/org/<seoname>/<id>/
```

Нужна редко: в выдаче и так почти всё. Берём её только за тем, чего в выдаче не бывает.

### Чего у Яндекса нет

**Почты.** Ни в выдаче, ни в карточке Яндекс не публикует email организации. Почта есть
только у 2ГИС — и это прямо влияет на главную колонку отчёта (ниже).

## Что из этого следует для программы

1. **Два источника дополняют друг друга, а не дублируют.** Яндекс даёт объём дёшево
   (25 организаций за запрос, с телефонами), 2ГИС — почты и соцсети, но по одному запросу
   на организацию. Поэтому сбор идёт с обоих и сводится в одну строку на фирму.
2. **Колонка «чего у фирмы нет».** Собрав одну и ту же фирму из двух карт, видно пробелы:
   нет почты, нет сайта, нет соцсетей, карточка не подтверждена владельцем, мало отзывов,
   фирма есть в одной карте и отсутствует в другой. Для холодных продаж это и есть товар:
   не «вот телефон», а «вот с чем к ним заходить».
3. **Сбор ограничен сверху.** 2ГИС — 60 объектов на запрос, дальше плитки; Яндекс —
   листание до исчерпания. Программа должна показывать, сколько собрано и где потолок,
   а не делать вид, что выгрузила «всё».
4. **Вежливость обязательна.** Паузы между запросами, один поток, повтор при сетевой
   ошибке. Сайты открытые, но нагрузку на них надо держать на уровне обычного посетителя.

## Что проверить, когда формат изменится

Источники живут своей жизнью. Признаки поломки и где чинить:

| Симптом | Где смотреть |
|---|---|
| «Состояние страницы не найдено» у 2ГИС | изменилось присваивание `var initialState = JSON.parse('…')` — `mapsparser/sources/twogis.py`, `_STATE_RE` |
| У 2ГИС приходит 0 объектов | переехал `data.entity.profile` |
| «Состояние страницы не найдено» у Яндекса | изменился `<script type="application/json">` или путь `stack[0].results` — `mapsparser/sources/yandex.py` |
| Контакты стали пустыми у всех | поменялись `contact_groups` (2ГИС) или `phones`/`businessLinks` (Яндекс) |

Сохранённые ответы обоих источников лежат в `tests/fixtures` — тесты идут по ним и
не ходят в сеть, так что поломку формата видно сразу по живому прогону, а не по тестам.
